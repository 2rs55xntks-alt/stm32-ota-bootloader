================================================================
  WI-FI 工程 —— 串口输出说明（USART2 / PA2，115200-8-N-1）
  每一次输出都对应本文件的一条；带 % 的是可变内容
================================================================

【约定】
  · 本文件列出的是「我们自己 printf 出来的」日志，全是简短的英文。
  · 模组（ESP-AT）自己吐出来的原文（OK / ERROR / +HTTPCLIENT:... 等）
    在最后第 6 节单独说明。
  · bootloader 没有串口，只能看 LED，见第 7 节。


================================================================
1. 启动 / 模组初始化阶段
================================================================
ESP32 init                  正在给 ESP32 发 AT+RST 复位（开机第一件事）
TX FAIL                     串口发送失败（USART1 硬件/接线问题），
                            这条可能出现在任何发 AT 指令的地方
AT TIMEOUT                  AT 指令在超时时间内没等到 "OK"
                            （2s / 15s，看是哪条指令）
STA                         设置 WiFi 为 Station 模式（AT+CWMODE=1）
join AP                     正在连路由器（AT+CWJAP，最长等 15s）
AP                          设置 WiFi 为 AP 模式（本工程默认用 STA，看不到）
wifi ok                     这条 AT 指令执行成功
wifi fail                   这条 AT 指令失败（模组回 ERROR 或超时）
+CIPSTA:ip:"x.x.x.x"        模组回报自己拿到的 IP（模组原文，不是我们打印的）
+CIPSTA:gateway:...         网关
+CIPSTA:netmask:...         子网掩码

2. 升级检查阶段（task.c）
================================================================
meta V3.0 18548             Metadata 里记着「上次下载成功过的版本」：
                            版本号 V3.0，18548 字节
no meta                     Metadata 区没有有效记录（刚擦过/第一次用）
chk wifi                    正在查 WiFi 是否已连上（AT+CIPSTATUS）
no resp                     模组对 AT+CIPSTATUS 无应答（模组死机/串口异常）
wifi no ip                  模组没连上路由器（没有 STATUS:2，即没拿到 IP）
wifi down, skip             WiFi 没连上，本轮跳过升级检查（继续跑旧程序）
rep 201                     上次升级刚装好，正在向平台补报 201（升级成功）
task V4.0 1535991 19888     平台返回的新任务：版本 V4.0，任务号 1535991，
                            固件 19888 字节
no task                     平台没有任务（或应答解析失败，详见 no json）
latest V4.0                 版本和大小都和平台一致，已是最新，不升级
new V4.0 19888              发现新版本 V4.0（19888 字节），准备下载
dl fail                     下载失败（失败原因会在这条之前打印，见第 4 节）
meta fail                   下载成功但写 Metadata 失败（Flash 擦写出错）
jump boot                   全部完成，置 BKP 标记并软复位，跳回 bootloader

================================================================
no json                     平台应答里没解析到 target/tid/size
                            （平台没任务、或返回格式变了）
task V4.0 1535991 19888     同上，解析成功

4. 下载阶段（OTA_Download / OTA_Load / OTA_BackupWrite）
================================================================
bad size                    平台给的 size 为 0 或超过 20KB（备份区装不下）
dl 1535991 19888            开始下载：任务号 1535991，共 19888 字节
erase fail                  擦除备份区（0x0800A000）失败
                            → 检查 Flash 写保护、供电是否稳定
rx fail <offset> <len> <step>
                            某一包重试 3 次仍失败，后面三个数字：
                              offset = 失败的位置（第几个字节）
                              len    = 这次实际收到的字节数
                                       len=1023 → 接收缓冲被灌满（内存溢出）
                                       len=0    → 一个字节都没收到（超时）
                                       其它     → 多半是模组回了 ERROR/CLOSED
                              step   = 上报给平台的错误码（见第 8 节）
len err                     服务器返回的字节数比请求的多（Range 没生效）
wr fail                     往备份区写 Flash 失败（地址/擦除/编程问题）
dl ok 19888                 下载完成，共写入 19888 字节

5. 上报阶段（OTA_Report，走裸 TCP）
================================================================
tcp fail                    连不上 iot-api.heclouds.com:80
                            （DNS 失败 / 网络断开 / 端口被封）
no prompt                   AT+CIPSEND 没给 '>' 提示符（模组忙）
rep ok <step>               上报成功，step 就是要上报的进度/状态码
rep rej                     平台收到了请求但返回 code 非 0（被拒绝）


================================================================
6. 模组（ESP-AT）自己打印的原文 —— 不是我们打的
================================================================
OK                          AT 指令执行成功
ERROR                       AT 指令被拒绝 / 执行失败
>                           AT+CIPSEND 的提示符，表示可以发数据了
CONNECT                     TCP 连接已建立
CLOSED                      TCP 连接已断开
SEND OK                     数据已发出
RECV X bytes                收到 X 字节
+HTTPCLIENT:<n>,<数据>      AT+HTTPCLIENT 的应答：后面跟 n 字节内容
                            （下载时是固件数据，查询时是一段 JSON）
+HTTPCPOST:<n>,<JSON>       POST 的应答（本工程已改用裸 TCP，正常看不到）
+IPD,<n>:<数据>             收到 TCP 数据（上报时里面是 HTTP 响应）
<html>...400 Bad Request    nginx 返回的错误页
                            → 说明 HTTP 请求被服务器判为非法
                              常见原因：AT+HTTPCHEAD 设置的自定义头没清掉
ready                       模组启动完成（复位后会有）
WIFI CONNECTED / GOT IP     模组连上路由器的通知


================================================================
7. bootloader（没有串口，只能看 LED：PB12，低电平点亮）
================================================================
LED 常亮                    搬运失败，或者没有有效固件：
                              · 备份区数据/元数据无效
                              · 擦除 / 写入 / 回读校验失败
                              · App 区向量表非法（跳不过去）
                            → 此时设备停在 bootloader 的 while(1)
LED 灭（或闪）              正常：新固件已装好并跳进 App，
                            或本来就没有升级任务，直接跳 App


================================================================
8. 上报给平台的 step 码表
================================================================
   0 ~ 100     下载进度（本工程每跨过 20% 报一次）
   101         升级包下载成功
   102         下载失败：空间不足
   103         下载失败：内存溢出（接收缓冲被灌满）
   104         下载失败：下载请求超时（一个字节都没收到）
   105         下载失败：电量不足（本工程不用）
   106         下载失败：信号不良（模组回 ERROR / CLOSED）
   107         下载失败：未知异常（擦除失败、写 Flash 失败等）
   201         升级成功（由新 App 启动后补报）
   202         升级失败：电量不足
   203         升级失败：内存溢出
   204         升级失败：升级包与任务目标版本不一致（本工程不上报）
   205         升级失败：MD5 校验失败（本工程不上报）
   206         升级失败：未知异常
   207         升级失败：达到最大重试次数（重试 3 次仍失败的兜底）
   208         升级失败：设备升级过期

9. 常见问题速查
================================================================
现象：开机只有 ESP32 init，然后没动静
原因：模组没上电 / 波特率不对 / USART1 接线错
排查：看有没有 AT TIMEOUT，用万用表量模组供电

现象：wifi fail 出现在 join AP 后面
原因：SSID/密码错、路由器信号弱、路由器限速
排查：确认 wifi.c 里的 SSID/密码

现象：wifi no ip
原因：连上了 AP 但 DHCP 没拿到 IP
排查：路由器是否开启了 MAC 过滤 / DHCP 池耗尽

现象：no json
原因：平台没任务，或返回的 JSON 字段变了
排查：抓一下模组原文，看 +HTTPCLIENT 后面是什么

现象：rx fail ... len=1023
原因：接收缓冲（1024 字节）被灌满，服务器没按 Range 返回
排查：检查 Range 头格式，或把 DL_CHUNK_SIZE 调小

现象：rx fail ... len=0
原因：模组一直没回数据（网络断了/服务器慢）
排查：重试几次；持续失败看 wifi no ip

现象：装完重启后一直 latest
原因：Metadata 已经写成新版本，但实际没装成功
处理：擦掉 0x0800F000 那一页（Metadata），让它重新下载

现象：bootloader LED 常亮
原因：搬运/校验失败
处理：重新上电再试；一直不行就用 ST-Link 重新烧 App

现象：下载到一半变成 HTML 错误页
原因：AT+HTTPCHEAD 设置的自定义头污染了后续请求
处理：本工程上报已改为裸 TCP，并在开机/下载前发 AT+HTTPCHEAD=0；
      若模组 NVS 里仍残留，执行一次 AT+RESTORE 恢复出厂
